## 1. Executive summary

Dockify is a well-shaped single-binary control plane: SQLite + SSH + Caddy admin API
+ Cloudflare, thin handlers over a service layer, embedded templates, mock mode, tests
for the risky pure logic (compose, migration, patch). That design should be kept.

What must change first (all cheap, together ≈ 200 lines):

1. **Cross-site WebSocket hijack of the root console** — `CheckOrigin` always true (S1).
2. **No CSRF defence** and session cookie without `SameSite`/`Secure` (S2).
3. **Caddy routes vanish on Caddy restart/reboot** — config is saved to the wrong file (B2). Confirmed live on `prod-heavy-1`: 17 routes in memory, 0 on disk.
4. **HTTP basic-auth apps are unreachable** — Dockify sends a Caddy handler that does not exist (B1).
5. **Undeploy leaves zombie apps / server delete fails** — foreign keys without cascade, DNS rows never deleted (B3).
6. **`docker volume prune -f` on every undeploy** can delete other apps' data on the same worker (B6).
7. **SSH host keys never verified** (S3) and **x/crypto has two reachable SSH CVEs** (S15).
8. **Open control plane by default** — `0.0.0.0` + no password unless configured (S4).

Everything else is medium/low and scheduled in §7.

## 2. How Dockify actually works today (corrects SPEC.md drift)

- `cmd/dockify/main.go` wires `config → db → server.Service (+Monitor) → scheduler →
  app.Service (+stats collector) → settings → backup → http.NewRouter`.
- One SQLite connection (`SetMaxOpenConns(1)`, WAL, `foreign_keys=ON`). Schema is
  `schema.sql` plus ~25 unconditional `ALTER`/`CREATE` statements run on every start
  with errors ignored (`internal/db/db.go`). 12 tables, not 8.
- Every remote action opens a **new SSH connection** via `ssh.Factory`
  (`internal/ssh/client.go`); commands are wrapped in `timeout -k 10 N sh -c '…'`.
  Files are written with a `cat <<'DOCKIFY_EOF'` heredoc.
- Background loops: server monitor every **10 s** (SPEC says 60 s) → `RefreshResources`
  (new SSH connection, 6 execs incl. `sleep 1`) and a `server_stats` row; app stats
  every 10 s (`docker ps` + one `docker stats --no-stream`), Caddy traffic every 30 s,
  disk every 5 min, prune hourly (7 days).
- Deploy (`app.Service.deployWithCommit`): write `.env` + files + compose → `compose
  down` → `compose pull` → `compose up -d --remove-orphans` → `docker image prune -f`
  → Caddy route per domain via the admin API (`docker exec caddy curl …`) → Cloudflare
  A record → status `running`, deployment `success`. Git webhooks only *trigger* this;
  nothing is cloned (`commit_sha` is informational).
- Auth: in-memory session map (lost on restart), optional bearer token. Webhooks are
  HMAC (GitHub) / shared token (GitLab) with the secret in `settings`.
- Files SPEC.md lists but do not exist: `server/web_handler.go`, `server/monitor.go`,
  `app/scheduler.go`, `app/logs.go`, `app/backup.go`, `settings/updater.go`,
  `backup/encryption.go`, `http/renderer.go`. Routes missing from SPEC:
  `/api/servers/{id}/prune`, `/servers/{id}/prune`, `/servers/{id}/stats`,
  `/apps/{id}/stats`, `/apps/redeploy-all`, `/apps/{id}/clear-deployments`,
  `/api/apps/{id}/stats*`, `/api/apps/{id}/traffic*`, `/api/apps/{id}/console`.

## 3. Security findings

Severity: High = network attacker or any website reaches admin/root; Medium = needs
admin or local foothold, or weakens a documented guarantee; Low = hygiene.

### S1 — WebSocket origin check disabled (High, confirmed)
- `internal/http/console.go:25` `CheckOrigin: func(*http.Request) bool { return true }`
  is shared by the server console, container console and both live-stats sockets.
- Impact: any web page the admin visits can open
  `ws://dockify/api/servers/{id}/console` with the admin's cookie (browsers that do
  not default cookies to `SameSite=Lax`, i.e. Firefox/Safari, or any Chrome profile
  once S2's cookie is set to `None`) and drive an interactive shell on the worker.
- Fix: delete the `CheckOrigin` line. gorilla's default rejects when `Origin` host ≠
  `r.Host`. Document that a reverse proxy must forward `Host`.
- Verify: `curl -i -H 'Origin: http://evil.test' -H 'Upgrade: websocket' … /api/servers/1/console` with a valid cookie → `403`.

### S2 — No CSRF protection; cookie lacks SameSite/Secure (High, confirmed)
- `internal/http/auth.go:48-54` sets `HttpOnly` only. Every state change is a plain
  form/HTMX POST with no token (`router.go` protected group); e.g.
  `POST /apps/{id}/undeploy`, `POST /api/backup/import`, `POST /api/settings/update/run`.
- Impact: cross-site form POST from an attacker page destroys apps / runs self-update
  on browsers without Lax-by-default.
- Fix (≈15 lines, no tokens): set `SameSite: http.SameSiteLaxMode`, set `Secure` when
  `r.TLS != nil || r.Header.Get("X-Forwarded-Proto") == "https"`; in `AuthMiddleware`
  for methods other than GET/HEAD/OPTIONS reject with 403 when
  `Sec-Fetch-Site` is `cross-site`, or `Origin` is present and its host ≠ `r.Host`.
  Bearer-token requests skip the check. HTMX and same-origin forms are unaffected.
- Verify: `curl -X POST -H 'Origin: http://evil.test' -b cookie /apps/1/stop` → 403; UI flows still work.

### S3 — SSH host keys never verified (High, confirmed)
- `internal/ssh/client.go:41` `HostKeyCallback: gossh.InsecureIgnoreHostKey()`.
- Impact: an on-path attacker impersonating a worker receives every command, the
  `.env` secrets, and the registry token piped to `docker login --password-stdin`
  (`internal/app/service.go:1230-1232`). Note `prepareDirectCopy` already pins host
  keys for worker↔worker copies (`service.go:595-610`), so the pattern exists.
- Fix (TOFU): add `servers.host_key TEXT DEFAULT ''`; `ssh.RealFactory(store)` where
  `store` resolves `host:port → key`; on first connect with an empty key, accept and
  persist `base64(key.Marshal())`; afterwards use `gossh.FixedHostKey`. Clear the key
  automatically when `host`/`port` changes; expose `host_key_clear` on
  `PATCH /api/servers/{id}` and a checkbox on the edit form. The console/stats
  handlers must use the factory instead of `ssh.Connect` directly
  (`console.go:94,185`, `stats_ws.go:58`, `app_stats_ws.go:70`).
- Verify: connect once; replace the worker's host key (or point `host` at another
  machine) → "host key mismatch for …" and status `error`.

### S4 — Control plane open by default (High, confirmed)
- `internal/config/config.go:24` default `DOCKIFY_HOST=0.0.0.0`; `main.go:84` only logs a
  warning when no password is set. Docker image hardcodes `DOCKIFY_HOST=0.0.0.0`;
  `scripts/install.sh:47` makes the password optional; docker-compose mode exposes 8080
  behind Caddy with no auth either.
- Fix: in `main` refuse to start when `AdminPass == ""` and the bind host is not
  loopback unless `DOCKIFY_ALLOW_NO_AUTH=true`; make `install.sh` require a password;
  README "No password set" paragraph updated accordingly.
- Verify: start without password on `0.0.0.0` → exits with the message; with
  `DOCKIFY_HOST=127.0.0.1` → starts.

### S5 — User strings reach the worker shell unescaped (Medium, confirmed)
Not privilege escalation (admin already has a shell) but breaks deploys with ordinary
input and is reachable through the API token, YAML import and S2.
- Domain → shell: `internal/caddy/client.go:82,133` interpolate the domain into
  `curl … /id/%s` unquoted; `CheckCertificate` likewise. A domain containing a space or
  `;` breaks or executes. No domain validation anywhere (`app/handler.go` Create/Edit,
  `backup.go` import).
- File path → traversal/injection: `service.go:232` `remoteDir + "/" + f.Path` with
  no `..`/absolute check; `ssh/client.go:219-226` quotes the path with `'…'` but does
  not escape `'`.
- File/compose/env content → heredoc: a line equal to `DOCKIFY_EOF` ends the heredoc
  and the rest runs as shell (`client.go:221-223`).
- `.env` writer `service.go:222`: key not validated (newline/`=` injection), value
  unquoted (compose `.env` parses `#`, quotes and spaces; multi-line values break).
- Simple-mode compose generator `compose.go:45-105` concatenates `image`, `command`,
  `ports`, `volumes`, limits into YAML unquoted (`command: a: b` → invalid YAML).
- Fix (smallest): (1) `WriteFile` = `ExecPipe("mkdir -p "+q(dir)+" && cat > "+q(path)+" && chmod "+mode+" "+q(path), strings.NewReader(content), nil)` using the existing `shellQuote`; (2) `validDomain` regex `^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?(\.[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?)+$` applied in both app handlers and the importer → 400; (3) file path: `path.Clean`, reject `/`-prefixed, `..` segments and chars outside `[A-Za-z0-9._/-]`; (4) env key `^[A-Za-z_][A-Za-z0-9_]*$`, value written double-quoted with `\`, `"`, newline escaped (`\n`) and `$`→`$$` kept; (5) build the simple compose with `yaml.Marshal` of a struct instead of string concatenation. One table test each.
- Compatibility constraint for (4), from production (24 live values with `"`, spaces,
  `$` or `#`): compose trims surrounding whitespace of today's unquoted values, so the
  writer must `TrimSpace` before quoting or apps would receive different bytes; inner
  `"` must be escaped, `$` stays `$$`. A ` #` inside an unquoted value is a comment
  today and becomes literal when quoted — that is the intended behaviour, but check
  the one production app whose value contains `#` after its first redeploy. The table
  test must contain exactly these shapes.

### S6 — `.env` written world-readable (Medium, confirmed)
- `service.go:225` mode `0644`. Any local user/container with host access reads app secrets. Fix: `0600` (compose runs as the SSH user). Config files stay `0644` (bind mounts into other uids).

### S7 — Self-update writes a predictable `/tmp` script and runs it as root (Medium, confirmed)
- `internal/settings/settings.go:118-125`: `/tmp/dockify-upgrade.sh` (0755) then
  `systemd-run … path`. A local user can pre-create a symlink or race the content →
  root. The script then `curl … main/scripts/update.sh | bash` (unpinned branch).
- Fix: no temp file: `systemd-run --no-block --unit=dockify-upgrade --collect /bin/bash -c "<script>"`.
  Pin the script to the release tag resolved by `CheckUpdate` and publish
  `sha256sum` in CI so `update.sh` can verify the binary.

### S8 — Webhook endpoint hardening (Medium, confirmed)
- "Disable" is broken: `settings.go:164` deletes the row, but `GetWebhookSecret`
  (`settings.go:141-147`) regenerates one on the next read, and `router.go`'s
  `webhookSecretFn` reads it per request → after "Disable" the webhook silently
  requires a **new random** secret the user never saw; the settings page shows it again
  on reload. Decision: remove Disable/Enable endpoints and buttons (fail closed, less
  code).
- Request bodies unbounded: `webhook/handler.go:35,78` `io.ReadAll` on a public
  route → `http.MaxBytesReader(w, r.Body, 1<<20)`.
- GitLab token compared with `!=` (`handler.go:102`) → `subtle.ConstantTimeCompare`.
- `GET /api/settings/update/check` is public (`router.go:58`) and `?force=1` bypasses
  the 5-minute cache → anyone can burn the GitHub API quota. Move it into the
  protected group.

### S9 — Login hardening (Medium, confirmed)
- `auth.go:114` compares user/password with `==` (timing); no throttling; the session
  map never drops expired entries. Fix: `subtle.ConstantTimeCompare` on both; on
  failure `time.Sleep(1 * time.Second)` and a per-IP counter (10 failures / 15 min →
  429); delete expired entries on each login. `chimw.RealIP` (`router.go:23`) trusts any
  `X-Forwarded-For`, so key the counter on `r.RemoteAddr` unless
  `DOCKIFY_TRUST_PROXY=true`.

### S10 — CORS wildcard on every route (Low, confirmed)
- `router.go:24,258-271` sends `Access-Control-Allow-Origin: *` with
  `Allow-Headers: Authorization`. Nothing in the product is cross-origin. Delete the
  middleware.

### S11 — Stored XSS through `nl2br` (Low, confirmed)
- `templates.go:214-216` returns `template.HTML` of the raw string;
  `apps_detail.html:115` pipes `App.Ports` (free text from the form/API/import) through
  it. Fix: `template.HTMLEscapeString(s)` before replacing newlines.

### S12 — Browser assets from CDNs without integrity (Low, confirmed)
- `layout.html:9-12` loads htmx, xterm and the fit addon from unpkg/jsdelivr with no
  `integrity`. A CDN compromise = admin session. Also breaks air-gapped installs.
  Fix: vendor the three files under `internal/http/static/` with `//go:embed` and
  serve them from `/static/*` (replacing the dead `web/static` route, B20). Add a
  `Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline' fonts.googleapis.com; font-src fonts.gstatic.com; connect-src 'self' ws: wss:` header once inline scripts are accounted for (templates use inline `<script>`; use `'unsafe-inline'` for `script-src` initially or move scripts out later).

### S13 — HTTP server without limits (Low, confirmed)
- `main.go:90-93`: no `ReadHeaderTimeout`/`IdleTimeout` (slowloris); JSON bodies and
  the import upload are unbounded (`backup/handler.go:52-61`). Fix:
  `ReadHeaderTimeout: 10s, IdleTimeout: 120s` (no global `WriteTimeout`: websockets
  and synchronous prune/import are long); `http.MaxBytesReader` 1 MiB for JSON
  handlers, 16 MiB for import; `r.ParseMultipartForm(16<<20)`.

### S14 — Key files outlive the server (Low, confirmed)
- `server/service.go:98-106` deletes the row only; `<id>.pem` and `<id>.registry-token`
  stay in `DOCKIFY_SSH_KEY_DIR`. Remove them after a successful delete.

### S15 — Vulnerable dependency (Medium, confirmed by govulncheck)
- `golang.org/x/crypto@v0.53.0`: GO-2026-6354 and GO-2026-6355 (SSH channel DoS)
  reachable from `ssh.Connect`. Fix: `go get golang.org/x/crypto@v0.56.0 && go mod tidy`.
  Add `govulncheck` to CI (A7).

### S16 — Secrets at rest are plaintext (Info)
- `app_secrets.value`, `apps.auth_pass`, SSH keys (0600 files). Acceptable for the
  single-binary design; document it under "Security Considerations". Not scheduled.

### S17 — Worker SSH key provisioning is inverted (Medium, confirmed on both workers)
- `scripts/setup-worker.sh:35-67` generates the key pair **on the worker**, appends
  its own public key to `authorized_keys`, then prints the **private** key for the
  operator to paste into the Add Server form, which stores it on the controller
  (`server/handler.go:289-294`). Both production workers still hold
  `~/.ssh/dockify` (the private key) next to a self-authorized `authorized_keys`.
- Why it matters: the private key crosses a terminal/clipboard (scrollback, shell
  history, CI logs if the script is ever run non-interactively) and lives on two
  machines; a compromised worker gives nothing extra (the key only opens that worker)
  but the flow trains operators to paste private keys. Host keys are also never
  pinned (S3), so the first paste is the only trust decision ever made.
- Fix (keeps the UI simple): generate the pair on the controller when a server is
  created (`crypto/ed25519` + `gossh.MarshalPrivateKey`), store it as `<id>.pem` as
  today, show the public key on the server page and in `GET /api/servers/{id}`;
  `setup-worker.sh` takes that public key as its only argument and appends it to
  `authorized_keys` (plus Docker install and `/opt/dockify` prep). Keep "paste an
  existing private key" as the advanced path. After migrating existing servers, delete
  `~/.ssh/dockify` on the workers. Scheduled in Wave 3.

## 4. Correctness bugs

### B1 — Basic-auth routes use a Caddy handler that does not exist (High, confidence high (static))
- `internal/caddy/client.go:51-70` posts `{"handler":"basic_auth","username":…,"hash":…}`.
  Caddy's JSON module is `http.handlers.authentication`; HTTP basic auth is the
  provider `http.authentication.providers.http_basic` with
  `accounts:[{username,password}]` (verified in Caddy source).
- Effect chain: `postRoute` first deletes any existing route for the domain
  (`client.go:80-84`), then the POST returns 400 (`unknown module`), so the app has
  **no route at all**, while the deploy is still recorded `success` (B4).
- Fix: build
  `{"handler":"authentication","providers":{"http_basic":{"hash":{"algorithm":"bcrypt"},"hash_cache":{},"accounts":[{"username":u,"password":bcryptHash}]}}}`
  followed by the `reverse_proxy` handler. `hash_cache` matters: cost-14 bcrypt
  (`client.go:52`) is ~1 s CPU per request on the worker without it.
- Verify (real worker): deploy an app with auth → `docker exec caddy curl -s localhost:2019/id/dockify-<domain>` returns the route; `curl -I https://<domain>` → 401; with credentials → 200.

### B2 — Caddy routes do not survive a Caddy restart or worker reboot (High, confidence high (static))
- Caddy is started with `caddy run --config /etc/caddy/config.json`
  (`server/service.go:235,279`; bind mount `/opt/dockify/caddy`). Routes are added via
  the admin API, and `SaveConfig` persists to **`/data/config.json`**
  (`caddy/client.go:149`), a different volume that nothing reads. `caddy run --config`
  ignores the autosave file (only `--resume` uses it).
- Effect: `docker restart caddy`, image update or reboot (`--restart unless-stopped`)
  brings Caddy up with the init-time base config → every app's domain is dead until
  each app is redeployed.
- Production has **both layouts**: `staging` runs `--config /data/config.json` with the
  host file bind-mounted there (older init), `prod-heavy-1` runs
  `--config /etc/caddy/config.json` with `/opt/dockify/caddy` mounted. A hard-coded
  `/etc/caddy/config.json` would fix prod-heavy-1 and break staging.
- Fix: `SaveConfig` persists to the path Caddy was started with: read the argument
  after `--config` from `docker inspect caddy --format '{{json .Config.Cmd}}'`, remove
  a stray directory at that path if present (prod-heavy-1 has one), then
  `curl -s localhost:2019/config/ -o <path>`; log the error instead of ignoring it.
  Unit-test the path extraction. Alternatively re-init `staging` so both workers share
  the current layout (InitWorker's migrate branch copies the running config first).
- Immediate mitigation on prod-heavy-1 (before any release): `docker exec caddy curl -s
  localhost:2019/config/ > /opt/dockify/caddy/config.json` as user `dockify`.
- Verify: deploy → `docker restart caddy` → `curl localhost:2019/id/dockify-<domain>` still 200.

### B3 — Undeploy/delete break on foreign keys; DNS rows never removed (High, confirmed by experiment)
- `schema.sql`: `deployments`, `routes`, `dns_records` reference `apps(id)` **without**
  `ON DELETE CASCADE`; `apps`, `deployments`, `routes`, `dns_records`,
  `container_stats`, `app_disk_stats` reference `servers(id)` without cascade.
  `foreign_keys=ON` is set (`db.go:25`).
- `Undeploy` (`service.go:362-422`) deletes routes and deployments but **never**
  `dns_records` (`repository.DeleteDNSRecords` at `repository.go:311` is dead code), then
  `s.repo.Delete(id)` with the error ignored (`service.go:371,380,419`). With Cloudflare
  configured, containers and `/opt/dockify/apps/app-N` are removed, then the row
  delete fails → a zombie app that still says `running` and can never be deleted.
- `server.Service.Delete` (`server/service.go:98`) → 500 `FOREIGN KEY constraint
  failed` as soon as the server has an app, a deployment or one stats row.
- Fix: migration (needs A1) rebuilding the child tables with `ON DELETE CASCADE` on
  `app_id` and `ON DELETE SET NULL`/CASCADE on `server_id`; `Undeploy` also deletes the
  Cloudflare records it created (`cloudflare.Client.DeleteRecord` exists, unused) and
  returns the delete error; server delete refuses with 409 while apps exist. Turn the
  experiment into `internal/db/fk_test.go`.

### B4 — Deployment is `success` although the route failed (Medium, confirmed)
- `service.go:297-308`: Caddy route errors are appended to the log but status still
  becomes `running` / `success`; `compose up -d` exiting cleanly does not mean the
  container stayed up. Fix: route failure → status `failed`, deployment `failed`
  (DNS failures stay warnings); optionally check `compose ps --status running` once.

### B5 — App lifecycle operations are not serialized (Medium, confirmed)
- Redeploy/Undeploy/Stop/Start/Rollback/webhook deploys/Redeploy-All each start a
  goroutine with no per-app lock (`app/handler.go:308,316,1161,1177,1197,1245`,
  `service.go:183,332`); only moves are guarded (`moving`). Concurrent
  `compose down/up` interleave; an undeploy during a deploy deletes the row while the
  deploy later inserts a deployment for a dead `app_id` (ignored FK error).
- Fix: `appLocks sync.Map[int64]*sync.Mutex`; wrap the bodies of
  `deployWithCommit`, `Undeploy`, `Stop`, `Start`, `MoveApp`, `CleanupFromServer`;
  handlers use `TryLock` and answer 409 "operation in progress". Fold the existing
  `moving` map into it.

### B6 — Global prunes on undeploy delete other apps' data (Medium, confirmed)
- `service.go:402-404` and `769-771` run `docker image prune -af`,
  `docker volume prune -f`, `docker builder prune -af` on the shared worker.
  `volume prune` removes every volume not attached to a container — e.g. the source
  copy of an app that is currently `down` for a move (`CopyAppFiles`,
  `service.go:505`), or any app the operator stopped with `compose down`.
- Fix: delete those lines. `compose down --volumes --rmi all` already removes the
  app's own resources; worker-wide pruning stays explicit via the Prune button.

### B7 — Network injection skipped when the compose text contains "dockify" (Medium, confirmed)
- `compose.go:118` `strings.Contains(compose, "dockify")` short-circuits for an image
  like `ghcr.io/coderbuzz/dockify` or a volume named `dockify_data` → the service is not
  on the `dockify` network and Caddy cannot reach it. Fix: inspect the parsed YAML
  (`services.*.networks` contains `dockify`), preferably on `yaml.Node` like
  `renameFirstService` so comments/order survive.

### B8 — Base-path mode broken for every POST (Medium, confirmed)
- `<base href>` honours `DOCKIFY_BASE_PATH`/`X-Forwarded-Prefix`, but all redirects are
  absolute: `auth.go:97,135`, `app/handler.go:778,1093,1163,…`, `server/handler.go`
  (~25 sites). Under `/proxy/9898` each form lands outside the prefix.
  `install.sh` asks for a base path, so the mode is advertised.
- Fix: one helper `Redirect(w, r, path)` that prepends `GetBasePath(r)`; replace all
  `http.Redirect(w, r, "/` call sites.

### B9 — Backup export loses app settings and extra domains; replace mode is unsafe (Medium, confirmed)
- `backup.go:52-63` `ExportApp` lacks `memory_limit`, `cpu_limit`, `log_max_size`,
  `log_max_file`, `command`, `ports`, `ulimits_nofile` and the route list; import
  recreates only `Domain`. `replace` mode runs synchronous SSH undeploys inside the
  request and ignores their errors (`backup.go:454-463`).
- Fix: add the fields plus `domains: []string` (export routes, import `SaveRoute`);
  for `replace`, refuse (409 "undeploy running apps first") unless every app is
  `draft`/`stopped` — least code, no half-applied state.

### B10 — Docker Compose install cannot save SSH keys (High, confirmed)
- `docker-compose.yml:11,16` mounts `${HOME}/.ssh` **read-only** and points
  `DOCKIFY_SSH_KEY_DIR` at it; "Add server" writes `<id>.pem` there
  (`server/handler.go:289-294`) → `save SSH key: read-only file system`. Install mode 1
  cannot add a worker through the UI.
- Fix: drop the `.ssh` mount and the env override; keys go to the `dockify_data`
  volume (`/var/lib/dockify/keys`, the default).

### B11 — Worker init is destructive on hosts that already run Caddy (Low, confirmed)
- `server/service.go:225,269` `docker rm -f caddy` and re-run with Dockify's config,
  also from the "migrate" branch; "Add server" auto-runs init including
  `curl get.docker.com | sh` (`server/handler.go:92-96`). `caddy:latest` unpinned.
- Fix: treat a `caddy` container as Dockify-managed only when its mounts include
  `/opt/dockify/caddy` (either layout, so both production workers qualify) or it
  carries the `dockify.managed=true` label that new inits add; refuse to touch any
  other `caddy`; pin `caddy:2`; keep auto-init but make it idempotent and
  non-destructive.

### B12 — Nil dereference on unknown server id in console (Low, confirmed)
- `console.go:71-75` checks `err` only; `Get` returns `(nil, nil)` for unknown ids →
  panic → 500 via Recoverer. Add `|| svr == nil` (the other handlers already do).

### B13 — Goroutine leaks per console session (Low, confirmed)
- `inCh` is never closed by the handlers, so the stdin forwarder
  (`ssh/client.go:263,339`) lives forever; `channelWriter.Write` (`client.go:370-375`)
  blocks forever once the WebSocket writer goroutine has exited. Fix:
  `defer close(inCh)` in both handlers; make `channelWriter` select on a done channel.

### B14 — Live app stats freeze after a container restart (Low, confirmed)
- `app_stats_ws.go:86-131`: when the `docker stats` stream ends, `StreamStats`
  returns, `snapCh` is never closed, and the poll fallback only starts if nothing ever
  arrived. Fix: loop `StreamStats` with a 1 s backoff until `ctx` is done.

### B15 — Stats cache ignores all-zero samples (Low, confirmed)
- `service.go:1079,1107`: a sample with 0 % CPU / 0 memory is dropped, so an idle app
  keeps its last busy numbers on the list/dashboard. Fix: overwrite whenever a sample
  arrived; keep the disk-only merge.

### B16 — Nested config-file paths cannot be deleted via API (Low, confirmed)
- `router.go:143` `{path}` stops at `/`. Use `{path:.*}`.

### B17 — No UNIQUE on `apps.name` though the code assumes one (Low, confirmed by experiment)
- `app/handler.go:1411` maps `UNIQUE constraint` to "an app with this name already
  exists"; backup import de-duplicates by name. Fix: migration
  `CREATE UNIQUE INDEX idx_apps_name ON apps(name)` (log and skip if existing data has
  duplicates); same for `servers.name`.

### B18 — Removed env vars/files linger on the worker (Low, confirmed)
- `service.go:224-236` writes `.env` only when non-empty and never deletes files
  removed in the UI. Fix: always write `.env` (possibly empty). Removed files: document
  (deleting requires remembering the previous set).

### B19 — Template errors produce half-rendered pages (Low, confirmed)
- `templates.go:265` writes the status before `Execute`. Render into a buffer first.

### B20 — Dead `/static/*` route with directory listing (Low, confirmed)
- `router.go:60-61` serves `web/static` (does not exist in the repo) relative to the
  CWD. Delete, or reuse for S12's embedded assets.

### B21 — Retention cutoff mixes local time with UTC text (Low, confirmed)
- `stats.go:749`, `server/service.go:467` pass `time.Now()` (local) while rows store
  UTC text; the 7-day window is off by the TZ offset. Use `.UTC()`.

### B22 — Route rows are duplicated on edit and move (Medium, confirmed on production)
- Production has 57 `routes` rows for 26 apps; app 6 (`services.amg.id`) has 19
  identical active rows, most apps have 2. No `UNIQUE(app_id, domain)` exists.
- Causes in `AppEditForm`: the primary domain is saved once in the `app.Domain` block
  (`app/handler.go:1033-1044`) and again in the loop over `domains`
  (`1046-1059`, `seen` does not include it); and in the move-without-files branch
  `DeleteRoutes` runs at `1015` **before** `oldRoutes` is read at `1028`, so every
  domain is re-added each time.
- Effect: `deployWithCommit` calls `setupRouteAndDNSForDomain` once per row
  (`service.go:298-301`): N Caddy posts, N Cloudflare lookups and up to N × 120 s
  certificate waits per deploy (app 6: 19×).
- Fix: migration that keeps one row per `(app_id, domain)` then adds the unique index;
  drop the first save block; read `oldRoutes` before deleting; `SaveRoute` uses
  `INSERT OR IGNORE`. Verify with
  `SELECT app_id, domain, COUNT(*) FROM routes GROUP BY 1,2 HAVING COUNT(*)>1` → none.

## 5. Architecture and performance

### A1 — Ad-hoc migrations with swallowed errors (Medium)
- `db/db.go:33-139` runs every migration on every start and ignores failures; there is
  no version. Real failures (disk full, locked DB) are invisible, and table rebuilds
  (needed by B3) are impossible this way. Fix: `PRAGMA user_version` + an ordered
  `[]func(*sql.Tx) error`, each run once in a transaction; `schema.sql` stays the
  baseline. ≈40 lines, one test.

### A2 — Abrupt shutdown and no recovery of in-flight deploys (Medium)
- `main.go:109` `srv.Close()`; `statsLoop` and `Monitor.Run` cannot be stopped; a
  deploy killed mid-way leaves the app `deploying` forever and the detail page in a
  2-second refresh loop. Fix: `srv.Shutdown(ctx 10s)`, a root context for the loops,
  and on startup set `deploying → failed` with a deployment log line "interrupted by
  restart".

### A3 — SSH connection churn (Medium, perf)
- Per worker every 10 s: monitor (new connection, 6 execs incl. `sleep 1`,
  `server/service.go:418,456`) + stats collector (new connection); traffic every 30 s;
  disk every 5 min; plus 3 execs/s per open live-stats page (`stats_ws.go:74-116`) and
  a synchronous `RefreshResources` on every resources-card request
  (`server/handler.go:585-590`). Fine for a handful of workers; beyond ~10 it is the
  first thing to hit. Cheapest wins: monitor to 60 s as SPEC says, compute CPU % from
  two consecutive ticks instead of `sleep 1`, and have the resources card read the DB
  instead of connecting. A per-server cached `*ssh.Client` with reconnect-on-error is
  the next step if measured.

### A4 — Dead and duplicated code (Low)
- `repository.FindByGitRepo` (`app/repository.go:113`) is unused and its SELECT lists
  19 columns but scans 21 → would fail if ever called. `DeleteDNSRecords`,
  `backup.encrypt`, `server/repository.go:202` `nullFloat64`/`nullInt64` unused.
  Three identical `Scan` blocks in each repository; metric parsers duplicated between
  `server/service.go` and `http/stats_ws.go`. Delete the dead code; share one
  `scanServer`/`scanApp` helper.

### A5 — SPEC.md is stale (Low, but it misleads implementers)
- See §2. Update file list, table count, monitor interval, routes. Do this in Wave 0
  so later sessions read a true spec.

### A6 — Server list cache goes stale (Low)
- `server/service.go:36-61` caches `List()`, but `UpdateStatus` callers
  (`TestConnection`, `InitWorker`) never refresh it, so list pages show old status
  until `RefreshResources` runs. One cheap query per page — delete the cache.

### A7 — CI only runs on tags; no formatting/vuln gate (Low)
- `.github/workflows/build.yml:3-5` triggers on `v*` tags only: PRs and `main` never
  run vet/test/smoke. Add `pull_request` + `push: branches: [main]`, `gofmt -l`
  (currently 16 files drift) and `govulncheck`. Release steps already gate on the tag.

### P1 — Single SQLite connection vs. 7-day chart queries (Medium)
- `db.go:20` one connection for everything. The 10 s collectors insert N rows per tick
  while `ContainerStats*History` aggregate up to 7 days of `container_stats`
  (≈60 k rows per container per week) with `strftime` per row; a 7d chart on a busy
  app can hold the only connection for hundreds of ms, stalling every handler and
  collector. Cheap now: `PRAGMA synchronous=NORMAL` (safe under WAL). If measured:
  a second read-only `*sql.DB` (WAL allows concurrent readers) or an hourly rollup
  table with raw retention cut to 48 h (7d charts already use 60-minute buckets).

### P2 — Minor N+1 and per-request copies (Low)
- `stats.go:649` queries routes per app every 30 s; dashboard copies the whole stats
  cache per request. Fine at current scale; note only.
